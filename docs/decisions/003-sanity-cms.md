# 003 — Sanity CMS로 콘텐츠 관리

## 결정
영상·웨비나 등 콘텐츠는 **Sanity CMS**로 관리하고, 프론트는 GROQ 쿼리로 가져온다.

## 배경
- 콘텐츠(영상, 웨비나 일정)를 **비개발자인 클라이언트(Tapas/Jez)가 직접** 추가·수정해야 함.
- 개발자가 매번 코드로 콘텐츠를 넣으면 운영이 불가능.

## 대안
- **DB(Supabase)에 콘텐츠도 저장**: 클라이언트가 직접 관리할 UI를 또 만들어야 함.
- **하드코딩**: 콘텐츠가 바뀔 때마다 배포 필요 — 운영 불가.

## 이유
- Sanity Studio(`/studio`)에서 클라이언트가 직접 영상·일정을 등록 (published/draft).
- 프론트는 published 콘텐츠만 GROQ로 조회해 표시.
- 콘텐츠와 코드를 분리 — 콘텐츠 변경에 배포가 불필요.

## 트레이드오프
- 외부 서비스(Sanity) 하나가 더 추가됨.
- 콘텐츠 구조(스키마) 변경 시 Sanity 스키마와 프론트 쿼리를 함께 맞춰야 함.
