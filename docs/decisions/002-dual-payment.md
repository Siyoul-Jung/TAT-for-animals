# 002 — Stripe + PayPal 이중 결제

## 결정
구독 결제를 **Stripe(메인) + PayPal(보조)** 두 수단으로 제공하고,
구독 상태는 각 결제사의 **webhook**으로 동기화한다.

## 배경
- 미국 사용자 대상 구독 서비스 — 카드(Stripe)와 PayPal 모두 흔히 쓰임.
- 결제 결과를 신뢰성 있게 받아 `profiles.role`을 갱신해야 함.

## 대안
- **Stripe만**: PayPal 선호 사용자를 놓침.
- **결제창에서 바로 role 부여**: 클라이언트를 신뢰하는 방식이라 위험 — 결제 완료를
  서버가 직접 확인하는 webhook이 안전.

## 이유
- 결제 완료는 결제사 서버가 보내는 webhook으로만 신뢰 (클라이언트 불신 원칙).
- 같은 알림이 여러 번 와도 안전하도록 **멱등성** 처리:
  webhook 이벤트 ID를 `processed_webhook_events`에 저장, 중복이면 건너뜀.
- 결제 실패/취소 등 상태 전이를 webhook 이벤트별로 매핑.

## 트레이드오프
- 두 결제사의 webhook·상태 모델을 각각 다뤄야 함 (복잡도 증가).
- 두 수단의 구독 상태 동기화 로직을 일관되게 유지해야 함.
